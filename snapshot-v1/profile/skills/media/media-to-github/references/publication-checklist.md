# Complete media-backed contribution checklist

Use this before showing a proposed public payload. It is a drafting aid, not publication permission.

## Private provenance and review packet
- Exact owner request, source message versus originating thread, proposal version and action.
- Designated media IDs, original/canonical URLs, creator, extraction/review dates and existing review result.
- Actual transcript/frame/slide coverage, time locators, ASR/OCR ambiguity, inaccessible/expired evidence and important missing intervals.
- Claim categories: direct observation; attributed creator claim; primary-source corroboration; inference; unknown.
- Current repository ID/base and exact target issue/PR/head; duplicate search and relevant existing coverage.
- Complete proposed public title/body and PR patch/files if applicable, plus privacy exclusions and action gates.
- Real approval and native subscription readbacks only after obtained. These private routing/approval details do not go in the public body.

## Public issue or PR body
- Explain what the source actually demonstrates and why the request matters; attribute creator claims and distinguish them from proposed behavior.
- Include only explicitly cleared public source URLs, brief relevant evidence with locators, and primary citations that support the exact claims made.
- State limitations, missing evidence, unverified compatibility/pricing/performance and the practical impact of uncertainty. Do not invent current capabilities, measurements or testimonial proof.
- Explain the problem/current coverage, desired outcome, proposed changes, non-goals, affected users/workflows and acceptance criteria.
- For every proposed skill add-on, name the section/file, exact wording or bounded behavior, evidence/rationale, verification and core-versus-reference placement.
- Explain alternatives, overlap, rejected ideas and reasons. Proposed work remains proposed until code/docs actually change.
- Link an existing relevant issue/PR rather than opening a duplicate. Preserve unrelated content when updating a target.
- Record actual tests/checks and pending checks distinctly. Do not publish internal scanner findings, private approval records or task references.

## PR-only completeness
- Exact repo/base/head, branch, bounded changed-file list and full reviewable diff presented privately before approval.
- Correct version allocation; authorship, license/provenance and contributor credit for reused work.
- Focused/full checks, test commands and actual results; unchanged scope and diff whitespace checks.
- New/changed instructions and reference closure scanned through native admission. Failure stops work; never force or switch importer to escape rejection.
- Risks, compatibility, dependencies/costs, privacy/security implications, rollout and separately authorized rollback plan.
- Keep installation/activation, merges, releases and deployment out of a PR-only action. Required CI must refer to the exact published head.

## Pre-write and recovery
- Recheck the current payload, target state, base/head, permissions, collision and matching owner approval.
- Material drift, unclear evidence, revoked/absent approval or a failed mandatory gate means no write.
- On timeout/uncertain write, inspect the exact remote result before retrying; do not create a duplicate.
- Verify the exact changed target after publication. Report factual drafted/queued/published/CI states separately.
